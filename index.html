Quick start

One prefix. Plenty to explore.

Madoka is a Discord bot that helps with server safety, moderation, music, and community tools. Its default prefix is >. Server administrators can change it with setprefix !; the exclamation mark is only an example. Slash commands can also be available in Discord's command menu.

Meet your toolkit

What can Madoka do?

A practical overview of the features available across the bot.

Protection

Anti-nuke & server safety

Help protect a server from destructive actions with trusted-user controls and configurable protection. Set the rules deliberately, test with trusted staff, and keep recovery access limited to people you trust.

Automatic care

Auto moderation

Configure automated rules, blocked words, exclusions, punishments, and logs to reduce repetitive moderation. Begin with conservative rules, review false positives, then adjust what is allowed or ignored.

Staff tools

Moderation & audit

Use moderation tools for member actions, warnings, message cleanup, channel controls, and server review. Check the target and requested action before running bulk or destructive commands.

Community

Welcome, roles & engagement

Build a warmer server with welcome messages, autoroles, reaction roles, leveling, birthdays, giveaways, tickets, and custom replies. Most features need a one-time setup and channel or role permissions.

Voice

Music & voice channels

Browse music playback and queue controls, plus voice-channel management such as join-to-create tools. The bot needs permission to view, connect to, and speak in the selected voice channels.

Everyday tools

Utility, fun & information

Find server and member information, reminders, polls, calculators, profile tools, games, and other handy commands. Use the searchable library below to check a command's purpose and usage.

Customization

Logging & server setup

Choose where supported events are recorded and configure the channels, roles, and messages used by server features. Keep log channels private when they contain moderation or member information.

How to add Madoka to your server

Open the Madoka invite page, sign in to Discord if prompted, select the server, review the permissions, and authorize the bot. You need permission to manage that server's integrations. After Discord redirects you back, check the member list to confirm Madoka joined.

Then allow Madoka to view and send messages in the channel where you will test it. Try >ping or use the command browser below. Ask a server administrator to review the invite permissions and role position before enabling moderation or protection features.

Permissions, roles, and server safety

Discord controls what Madoka can do. Give it only the permissions its enabled features need, and keep its role below roles it should not manage. Commands such as ban, kick, channel locking, and role management depend on both Discord permissions and the bot role's position.

Use destructive actions carefully, review the target before confirming, and avoid sharing private tokens or account credentials. If a command is denied, check the bot's channel access, role position, and the permissions of the person running it.

Anti-nuke: enable protection carefully

Start by choosing a private log channel and deciding which owner or staff accounts are trusted. Search the command browser for antinuke to confirm the exact setup commands supported by your server; command names and available thresholds can differ. The example >antinuke enable is only a hint, not a guarantee of the command syntax.

Review the action limits, alerts, and whitelist before enabling protection. Add only people you already trust, test with a small staff group, and verify that Madoka's role can perform only the recovery actions you intend. Keep the log channel private and have a trusted administrator check the configuration after activation.

How do I get no-prefix access?

No-prefix lets members run supported commands without typing the server prefix. For example, >ping becomes ping. It is included with every Premium plan.

AutoMod: rules, exclusions, and logs

AutoMod can help apply consistent rules to common message patterns. Decide what should trigger a rule, what action should happen, and where staff can review the result. The example >automod opens the feature's setup or help path where supported; use the command library below to find the exact command syntax available to your server.

Add exclusions carefully for trusted channels or roles, then test rules against harmless examples. Monitor false positives, make sure staff can see the configured log channel, and update the rules when your community's needs change.

Prefix and slash commands

The default prefix shown for Madoka is >. A server administrator can change it with setprefix !; ! is just an example, and your server may use a different prefix afterward. Put the active prefix directly before a prefix command, such as >help with the default.

Slash commands are selected from Discord's built-in command menu and do not need a message prefix. Availability can depend on the command and server configuration. If a command appears unavailable, check whether it is prefix-based or slash-based and whether the bot has permission to respond in that channel.

Music and voice troubleshooting

For music commands, join the voice channel first and check that Madoka can view and connect to it. If playback or a command does not work, confirm the bot is online, the channel permissions allow it, and the command is available to your server. The bot may also need permission to speak, and the voice channel must not be full or otherwise inaccessible.

Some features require additional Discord permissions or server setup. Check the relevant category guide and ask in the support server if the issue continues. For join-to-create voice features, review the configured parent category and permissions before testing with a member account.

Community tools and integrations

Madoka's listed community tools include welcome messages, automatic roles, reaction roles, leveling, birthdays, giveaways, tickets, polls, custom replies, and invite tracking. These features help staff welcome people, organize support, and encourage participation. Check each command's description for the action it supports; many setup commands need a channel, role, or log destination chosen first.

Additional integrations such as Minecraft, join-to-create voice rooms, and Premium tools may need separate setup or access. Their availability can depend on the server and bot configuration, so check the command library and the bot's response instead of assuming an integration is enabled.

Privacy, logs, and safe bot use

Server moderators control which logging and moderation features they enable. Keep log and support-ticket channels visible only to the staff who need them, and review your server's own privacy rules before enabling member-tracking features such as invite or activity tools.

Never share bot tokens, passwords, or private credentials in commands, screenshots, or support requests. Give Madoka only the Discord permissions its enabled features require and review role access regularly.

A command is not responding — what should I check?

First check that Madoka is online, that you are using the server's active prefix or a supported slash command, and that the bot can view and send messages in that channel. Check your own Discord permission, the bot's role position, and whether a feature needs a one-time setup.

For a denied action, review role hierarchy and channel overrides. For a setup issue, try the relevant help or configuration command from the library below. If the problem remains, create a ticket in the support server with the command name and a safe description of what happened—never include tokens, passwords, or private credentials.

Where to get help

For help from the team, join the support server and create a ticket for errors, bug reports, or Premium questions. You can also visit the Madoka Developers page to contact the team directly.
